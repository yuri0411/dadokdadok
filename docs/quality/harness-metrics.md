## 확인된 성과

하네스 도입 과정에서 다음 상태 오류 두 건을 수정하고 회귀 테스트로 고정했다.

1. 다른 레벨을 학습할 때 기존 레벨의 최근 학습 기록이 사라지는 문제
2. 처음 학습하는 단원의 진행 상태가 빈 배열 구조 대신 빈 객체로 반환되는 문제

현재 자동 검증은 다음 계약을 포함한다.

- 아키텍처 규칙 12개: 금지 사례 10개와 허용 사례 2개
- 학습 상태 테스트 10개: 학습 기록, 회독, 진행 상태, 시간, 복습 데이터의 저장·복원·이관
- 학습 화면 통합 테스트 9개: 즉시 저장, 완료 판정, 복습 목록, 시간 중복 방지, 최근 학습 위치, 단원 이동, 키보드 모달 흐름
- PR 검사 4개: `lint`, `typecheck`, `test`, `build`

PR 검사 4개는 하네스 도입 전에도 존재했다. 하네스의 성과는 검사 개수의 증가가 아니라 같은 `lint`와 `test`가 아키텍처 경계와 핵심 학습 회귀까지 차단하게 된 것이다.

## PR별 운영 지표

각 PR의 템플릿에 아래 항목을 기록한다.

| 지표 | 기록 방법 |
|---|---|
| 첫 CI 결과 | 최초 실행에서 필수 검사 4개가 모두 통과했는지 기록 |
| 실패 검사 | 최초 실행에서 실패한 검사 이름 기록 |
| 수정 후 재실행 | 실패 원인을 고치고 다시 실행한 횟수 기록 |
| 테스트 변화 | 전체 테스트 수의 변경 전·후 기록 |
| 발견한 회귀 | 테스트 또는 정적 검사로 발견해 수정한 문제 기록 |

데이터가 쌓이면 다음과 같이 계산한다.

- 첫 CI 통과율 = 첫 실행에서 모두 통과한 PR 수 / 전체 PR 수
- 평균 재실행 횟수 = 수정 후 재실행 횟수 합계 / 전체 PR 수
- 자동 발견 회귀 수 = `발견한 회귀`에 기록된 문제 수

## 갱신 방법

하네스 범위가 달라지거나 의미 있는 회귀 테스트를 추가했을 때 스냅샷 행을 추가한다. PR별 운영 지표는 각 PR 설명에 남기고, 월별 또는 릴리스 단위로 이 문서에 집계한다.

숫자를 갱신할 때 실행한 커밋과 명령을 함께 기록한다. 실행하지 않은 검사나 서로 다른 커밋의 결과를 하나의 스냅샷으로 합치지 않는다.

아직 배포 후 버그 발생률, 개발 시간 절감률, 코드 커버리지 비율은 측정하지 않는다. 데이터가 없으면 개선 효과로 추정해 기재하지 않는다.
